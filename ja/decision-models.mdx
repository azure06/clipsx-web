判定モデルは、コピーした文章への「はい／いいえ」の質問を評価します。一致したときにタグ、お気に入り、ピンを追加するか、非公開、秘密情報、保存しない、のいずれかを選びます。生成モデルは文章を作り、判定モデルは条件に一致するかを評価します。

このガイドは **ClipsX 0.1.8以降**が対象です。ルールは新しいテキストのコピーに適用されます。既存の履歴や画像のピクセルは検査しません。

## 用途ごとのモデル割り当て {#assignments}

| 割り当て | 用途 |
| --- | --- |
| **一般的な判定（General decisions）** | タグ、お気に入り、ピンのルール、拡張機能の自動実行条件、許可された拡張機能からの判定要求 |
| **プライバシー判定（Privacy checks）** | 資格情報の分類、非公開、秘密情報、保存しない、のルール |
| **拡張機能の文章生成** | RewriteなどのAI拡張機能による結果の生成 |

プライバシーは整理ルールより先に評価されます。秘密情報や非公開と判定されたクリップは、一般的な判定モデルへ送られません。ただし、プライバシー判定の提供元は評価対象の文章を受け取ります。端末内に保つ必要がある場合は端末内の推論を使ってください。

## 判定モデルを設定する {#setup}

1. **インテリジェンス → モデル**で接続を追加または選択します。判定プリセットはOllamaとOpenRouterに対応します。通常のチャットモデルが判定にも対応するとは限りません。
2. ローカルのOllamaでは、対応するSystem One判定モデルを導入します。アプリではLayaを例として案内しています。

   ```shell
   ollama pull laya
   ```

3. モデル一覧を更新し、用途を**判定（Decision）**にしたプリセットを作成します。導入済みモデルを選び、判定のテストで接続と応答を確認します。
4. **用途と既定値（Usage & defaults）**で一般的な判定、プライバシー判定、または両方に割り当てます。用途ごとに異なる提供元を選べます。

別の提供元への自動切り替えはありません。ローカルの接続先でもクラウドモデルを使う場合があります。Ollamaがダウンロード済みのローカルモデルを使っていることを確認してください。[ローカルAIの設定](/ja/local-ai)も参照してください。

## 整理ルールを試す {#first-rule}

1. **インテリジェンス → 判定ルール**でルールを追加します。
2. 名前を **Debugging**、質問を**ソフトウェアのエラーについて書かれていますか？**にして、**タグを追加**で **Debugging** を指定します。
3. ルールのテストで下書きを選び、次の両方を試します。

   ```text
   接続がタイムアウトし、アプリが終了しました。
   ```

   ```text
   チームのランチは木曜日です。
   ```

4. 結果を確認して質問を調整し、ルールを有効にして保存します。安全なサンプルをもう一度コピーし、履歴のタグを確認します。

テストではサンプルだけを割り当て先に送信し、保存や操作は行いません。「はい」が**50%以上**なら一致します。この数値はモデルの判断であり、正解率ではありません。一致してほしくない例も含めて試してください。

## 保存を制限する {#privacy-actions}

組み込みの秘密情報検出はモデルなしでも動作します。プライバシー判定を割り当てると、モデルによる資格情報の分類と、**顧客の機密情報が含まれていますか？**などの独自ルールを追加できます。

| 操作 | 一致したときの動作 |
| --- | --- |
| **非公開にする** | 保存しますが、Recall、意味検索、MCP、自動拡張処理の対象外にします |
| **秘密情報にする** | 同じ処理制限を適用します。「検出した秘密情報を保存しない」の設定により保存も制限できます |
| **保存しない** | 今回のコピーをClipsXに保存しません |

認識した資格情報を保存前に除外するには、**検出した秘密情報を保存しない**を有効にします。システムのクリップボードやコピー元の内容は変わりません。過去の履歴も削除しません。本物の資格情報をテストに使わないでください。

## 判定に失敗した場合 {#failed-checks}

タイムアウト、接続不能、不正な応答、入力上限の超過などで判定できない場合、クリップ全体を**未確認（Not checked）**の表示付きで保存します。失敗しただけでは非公開にならず、Recall、意味検索、有効な拡張機能から利用できる場合があります。プライバシー判定に失敗すると整理ルールは実行しません。既存の制限や正常に検出した秘密情報には、それぞれの除外設定が適用されます。

「いいえ」は安全の証明ではありません。すべての秘密情報や機密文章の検出を保証するものではありません。未確認の表示が出たら、割り当て、接続、入力サイズを確認してください。

## 条件に合うときだけ拡張機能を実行する {#automation}

自動実行ルールでは、翻訳が必要な文章かを判定してから翻訳用の設定を実行できます。条件には一般的な判定を使い、Rewriteの出力には文章生成を使います。

[条件付き自動実行](/ja/automation)または[MCPの接続](/ja/assistant-setup)へ進んでください。
