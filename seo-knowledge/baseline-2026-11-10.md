# Baseline — 2026-11-10

First full collection run. Sources: live sitemap crawls (verified twice),
Google autocomplete API (suggestqueries, EN+JA), Search Console checked
2026-11-10 (data through Nov 7). Raw snapshot:
`snapshots/baseline-2026-11-10.json`.

## 2. Search Console reality (both sites)

- ClipsX 28d: 9 clicks / 190 imp, all brand or typos. **Zero generic clicks.**
  /en/download gets 39 impressions and 0 clicks — people see it, don't click.
- XKey 28d: 11 clicks / 161 imp; **/ja alone = 8 clicks**. Queries all brand.
- Indexing: no big technical bug. 11 pages requested 2026-11-10 (7 xkey,
  4 clipsx docs); docs/recall pending quota (retry scheduled Nov 11).
- Blog pages are indexed but invisible: ≤2 impressions per ClipsX blog URL.

Conclusion: both sites are *findable for their own names only*. Growth has to
come from problem queries other people already search — which is what the
demand data below maps.

## 3. What people actually type — autocomplete evidence (2026-11-10)

Autocomplete returns the phrases Google real users type. Highlights:

**ClipsX — strong problem demand around built-in limits:**
- "windows clipboard history limit", "windows 11 clipboard history limit",
  "windows clipboard history limit increase", "windows clipboard history
  increase limit" — direct demand for the limits article (already drafted,
  PR branch pending).
- "windows clipboard history not working", "pin to top", "location",
  "turn off" — a cluster of how-to/problem queries with no strong owner.
- Mac: "mac clipboard history free", "mac clipboard history open source",
  "mac clipboard history like windows", "mac clipboard history app" —
  ClipsX is literally free + open source + cross-platform; winnable framing.
- JA: 「クリップボード 管理 フリーソフト」「クリップボード 管理 アプリ windows/mac」
  「クリップボード 履歴 復元」「windows クリップボード 履歴 上限 増やす」 —
  Japanese demand exists for both the limits topic and recovery topic.
- **Zero suggestions for "semantic search clipboard"** — nobody types it.
  Meaning Search is a feature story to attach to problem articles, not a
  search term to target head-on. (Checked fact, not opinion.)

**XKey — demand expresses differently than we assumed:**
- "powerpoint file too big" cluster is rich: "too big to email / to send /
  to open / to send outlook", "ppt file too big" — file-bloat is the demand.
- **Zero suggestions for "powerpoint too many slide masters"** — the exact
  pain phrase nobody searches. Reframe: target "powerpoint file too big"
  and make slide masters one cause/fix inside it.
- Slide master demand is how-to/problem shaped instead: "slide master not
  updating / not applying / footer not showing"; JA「スライドマスター
  反映されない」「削除できない」「差し替え」「使い方」 — matches XKey's /ja strength.
- Shortcuts: "powerpoint shortcut keys", JA「ショートカットキー 一覧」
  「早見表」 — XKey's /product/shortcuts is already indexed; a real
  shortcut-list resource (EN+JA) has proven demand behind it.

## 4. So the bottleneck, in order

1. No pages targeting proven problem queries (except the pending article).
2. Indexed blog content aimed at topics nobody searches (local-first/AI
   themes) — visibility ≈ 0 despite being indexed.
3. /en/download: 39 imp / 0 clicks — title/meta or intent mismatch worth
   fixing once we see more query data for that page.
4. JA is under-served on both sites relative to its demand (XKey /ja already
   proves Japanese converts to clicks).
