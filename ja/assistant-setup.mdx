コピー済みの顧客報告、APIメモ、エラー、参考資料が必要なとき、アシスタントから関連クリップを検索して原文を確認できます。資料を一つずつ貼り直す手間を減らせます。

ClipsXのローカルサーバーは **Streamable HTTP MCP**に対応し、既定では無効です。ClipsXの起動が必要です。既定の接続先は `http://127.0.0.1:39389/mcp` で、詳細設定でポートを変更できます。ウィンドウを隠してもサーバーは動作します。

## 最初のアシスタントを接続する {#setup}

1. **インテリジェンス → 連携**でサーバーを有効にします。
2. アシスタントを追加し、Codex、Claude Code、汎用のテンプレートから選んで、名前付きのアクセスを作成します。まず**読み取り専用**を使います。
3. 実際のクライアントに合う生成済みの案内に従います。トークンは秘密にしてください。ClipsXでアクセスを作るだけでは外部アプリは設定されません。
4. 指示どおりクライアントを再起動します。ClipsXでアクセスをテストした後、安全な保存メモを探すようアシスタントに頼みます。

アクセスのテストは認証とツール一覧を確認します。外部クライアントの設定や、モデルが適切にツールを使うことまでは確認しません。

### CodexのデスクトップとCLI

OSとクライアントに合う案内を使います。CLIへの登録だけでなく、実行プロセスからトークンを参照できる必要があります。Windowsデスクトップでは表示されたユーザー環境変数の保存手順に従い、バックグラウンドを含めてCodexを完全に終了し、開き直してください。新しいチャットを開くだけでは環境変数は更新されません。

Windowsの永続的な環境変数はClipsXの保護された資格情報ストレージとは別です。トークンや設定済みコマンドを共有ファイルやスクリーンショットに含めないでください。接続できない場合は設定画面の接続トラブル案内を確認します。

### Claude Codeとその他のクライアント

生成されたHTTP設定とBearer認証ヘッダーを使います。テンプレートは設定を補助するもので、対応クライアントを制限しません。クラウド上のアシスタントから端末のループバックアドレスには直接接続できません。ClipsXは公開トンネルを作成しません。

## 根拠を使った検索を試す {#first-task}

次のメモを別々にコピーします。

```text
Orionの顧客報告：同時に2件の注文を送ると30秒後にタイムアウトする。
```

```text
OrionのAPIメモ：クライアントの既定タイムアウトは30秒。注文失敗の原因は未確認。
```

**コピーしたOrionの報告とAPIメモを探し、根拠と未確認事項を分けて開発者への引き継ぎを作って**と依頼します。原文を読んでから回答しているか確認してください。タイムアウトの時間が同じでも原因の証明にはなりません。

キーワード検索にClipsX側のAIモデルは不要です。意味検索には有効な埋め込みモデルと索引が必要です。外部アシスタントは自身のモデルを使うため、MCPでクリップを公開するだけならClipsXの生成モデルは不要です。

## アクセス権を選ぶ {#permissions}

| アクセス | ツール |
| --- | --- |
| **読み取り専用** | `get_clipboard_status`、`list_clipboard_filters`、`search_clips`、`read_clip`、`read_clip_image` |
| **読み書き** | 読み取りツールに加え、`create_clip`、`organize_clips`、`undo_clipboard_action` |

読み取りは対象の保存済みテキスト、既存OCR、対応画像プレビューに限られます。ファイル参照から端末内の任意ファイルへはアクセスできません。書き込みは対応する作成と整理であり、シェルや任意ファイル、履歴削除へのアクセスではありません。作成したクリップは履歴に追加され、システムのクリップボードは置き換えません。対応操作は取り消せますが、後から編集された場合などは拒否されます。

ClipsXは検索方法を案内しますが、実行するかはアシスタントが判断します。検索結果だけで結論を出さず、原文を確認してください。最近の変更履歴はMCPの変更操作を記録し、すべての読み取りを記録するものではありません。

## 接続を管理する {#access-control}

アシスタントごとに別のアクセスを作成します。トークンは作成時または更新時だけ表示されます。紛失したら更新し、クライアント側を置き換えて再起動します。更新または失効すると、そのアシスタントのセッションは直ちに切断されます。サーバーを無効にするとすべて切断されます。

失効は項目を残して無効にし、削除は保存済みアクセス設定を取り除きます。クリップと保持された操作履歴は残ります。外部クライアントの設定や環境変数は自動削除されません。

秘密情報や非公開のクリップはアクセス対象外です。ただし、プライバシー判定の失敗だけでは制限されません。[失敗時の動作](/ja/decision-models#failed-checks)を確認してください。

接続はローカルでも、外部アシスタントは取得した内容を自身の提供元へ送信する場合があります。MCPのアクセス、接続先設定、操作履歴は端末ごとに保存され、設定同期の対象外です。[プライバシー](/ja/privacy)も参照してください。
